## Packaging Tools {#PackagingTools}

The Packaging Tools area allows Create New Demo Projects as well as Open Existing .packaginfo.json files.   Packaging Projects allow you to create a file in OPV Format which includes all of the necessary components needed to distribute your application or install it on the target.  

**New Button** - This button allows you to access any of the demo / starter projects you have downloaded.   Demo Projects are available in the Plugin Manager.

**Open Button** - Opens a PackageInfo.json file for your project allowing you to change the inputs, output and project attributes.

## Packaging Options {#PackagingOptions}

Once you have opened a Packaging project file, you can edit the various values which control how your project will be built or downloaded.

**Package Name** - The Name of your package.  This name will also be used by the Spark OTA feature when uploading your application. 
 
**Target Platform** - The Platform for your Application.  This is a combination of the Platform Family (OS) and Platform Qualfier (Variant) and defines what dependency packages will be included in your resulting Package File.
 
**Application Type** - Selecting the Application Type will allow you to access any extra settings that are available based on the selected Language / Framework Technology.

**User Interface Type** - Selecting the User Interface Type will allow you to access extra settings that are available based on the selected UI Technology.

**Application Version** - Allows you to define an Application Version to be reported to the system at runtime or when uploading to Spark.

**Application Output** - Specifies the path relative to the package info file where the applications output will be captured.  This folder will be packaged and included in the OPV file generated by the tool.

**Package Output** - Specifies the path where the resulting OPV file will be saved after its generated.

**Execute Command** - This is the command that will be used to start your application on the target.  Typically this is the name of your executable located in the Application Output folder.

**Start Logo** -This is the path to the Startup Logo which will display at display bootup.

## Packaging Commands {#PackagingCommands}

**Generate Package** - Creates a OPV Package file from the selected PackageInfo.json file.   This packages the content of your application along with dependencies needed based on your selected Project Type (DotNet, Node, etc).  

**Delete Package** - Deletes the OPV Package from the Output Folder.  

**Show Package Folder** - Opens an Explorer or Shell Window showing the Package Folder.  

**Load To Display** - Loads the generated package to the display. Note that the button will only function when in the Visual Installer (Ahsoka.InstallerUI).  If you are currently running a customer application the icon on the bottom right of the Status Bar (Stop Application) will stop the application and return to the installer.  

## Spark OTA  {#SparkOTA}

This tab allows you to configure and upload OPV Package Files to Spark for use in OTA Updates.

**Development Team** - All Spark Packages are uploaded in the context of a Team.  Select your team to associate this package and any provisioned displays with this Team.  

**Application ID (AppID)** - The Application ID is a unique ID that is used to track your Application in Spark.  Its also the ID used to allow devices to check for upgrades of installed application.  Because of this, the AppID should be set one time (using "Update App ID") and saved.  As you upgrade and update your application, the AppId will be used by displays in the field to find that new updates that are available.  The combination of AppID and Package Name represent the Spark "Channel" which the displays will subscribe to.  

## Spark Commands {#SparkCommands}

**Update APP ID** - Generates a new AppID for the package.  

**Provision Display** - Subscribes the display to the AppID / Package Combination and adds the Device to Spark allowing it to Call Home and check for updates.  

**Upload to Spark** - Uploads the OPV File you have generated to Spark in the Most Restrictive Channel (Development) allowing you to begin testing your application on development devices.

## DotNet Setup Options {#DotNetOptions}

**DotNet Project Name** - Path to a DotNet Project file (csproj) allowing the toolkit to execute a build during the generate process.  

**DotNet Publish Profile** - Path to a publishing profile for the Development Target (Typically Linux/ARM or Linux/ARM64).  This will allow the generation process to correctly publish your application.  The output of this publish profile should be your output directory.
